# ip-triage

Подбор VPS-хостера под узел, который должен быть доступен из России (VPN/прокси-узел, мост,
игровой выход — любой проект): оценка сети хостера до покупки и проверка сервера после.

## Зачем

Хостер может дать IP, который уже заблокирован в РФ, лежит в «грязной» подсети, режется на
мобильных операторах или вообще принадлежит чужой сети (перепродавец). Проверить это заранее
до конца нельзя, но можно сильно сузить круг: сколько адресов сети уже в чёрных списках, сколько
в белых списках мобильных операторов, отвечает ли IP из РФ, не рвёт ли DPI поток на 16–20 КБ.

## Скрипты

| Скрипт | Что делает | Запуск |
|---|---|---|
| `fetch_lists.py` | качает свежие чёрные и белые списки CIDR в `data/` | `python fetch_lists.py` |
| `resolve_asn.py` | подсети ASN (RIPEstat, запасной — ipverse), тип сети по PeeringDB | `python resolve_asn.py 24940 [--json]` |
| `score.py` | доля «палёного» и «белого» пространства у ASN, флаг недружественных ASN, отчёт в `reports/` | `python score.py 202053 --name upcloud` |
| `score_all.py` | то же пачкой по файлу `hosters.txt` (`ASN<TAB>имя<TAB>заметка`) | `python score_all.py [--input f] [--out dir]` |
| `country_whitelist.py` | какие сети **страны** попадают в белый мобильный список РФ (RIPE delegated ∩ список, группировка по ASN) | `python country_whitelist.py FI out.json` |
| `country_score.py` | доля белых/чёрных адресов у ASN **только по его префиксам в заданной стране** (гео каждого префикса по RIPEstat) — для хостеров с сетями в разных странах | `python country_score.py FI candidates.txt out.json [--cap 800]` (файл: строки «ASN название») |
| `probe.py` | отвечает ли IP из РФ: TCP с 3 узлов check-host RU + ping/HTTPS с 5 проб Globalping; можно сузить до города/оператора | `python probe.py 1.2.3.4 5.6.7.8 [--port 443] [--sni host] [--city Novosibirsk] [--asn 8359]` |
| `vps_probe.py` | запускать **на купленном сервере**: репутация IP, Spamhaus, связность с РФ (см. ниже) | см. раздел ниже |

Отчёты — в `reports/YYYY-MM-DD-<hoster>.md`.

## Глубина поиска (обязательно)

Скрипты проверяют только тех кандидатов, которых им дали. Подбор с первой страницы
поисковика (4–5 хостеров) дал два выброшенных сервера; рабочий подбор 09.2026 — 3,5–4 часа
на 7 стран, **20–30 хостеров в длинном списке на страну**, несколько страниц выдачи на двух
языках, LowEndTalk/LowEndBox, looking.house, каталоги, хостинговые ASN страны
(`country_whitelist.py`, PeeringDB, bgp.he.net), отзывы РФ-аудитории, тест-IP у каждого,
итог — топ-3 на страну. Требования и шаблон задания для подагентов —
`MeerGuardNetwrokKnowledge/knowledge/Руководства/Подбор хостера для узла, доступного из РФ (ip-triage).md`.

## Порядок подбора хостера для страны (проверенный на практике, 09.2026)

1. `fetch_lists.py` — освежить списки.
2. `country_whitelist.py <CC>` — какие сети страны «белые» для мобильных РФ.
3. Собрать кандидатов (поиск, LowEndTalk, looking glass): для каждого — **тестовый IP в этой
   стране**, тариф, оплата (какая крипта, какая карта), верификация, запрет VPN в ToS.
4. Реальная сеть тест-IP по RIPEstat — **для каждой локации отдельно**: перепродавцы часто сидят
   на чужой сети (пример: «финский» EDIS — это M247, польский YottaSrc — OVH). Отсечь
   недружественные ASN (список ниже, плюс M247, Datacamp, WorldStream, Vultr).
5. `country_score.py <CC>` по ASN кандидатов — чистота сети именно в этой стране.
6. Соседи-выходы Tor в /24 и в AS (много — риск проверки Cloudflare на сайтах).
7. `probe.py` по тест-IP, пачками до ~8 адресов (Globalping отвечает 429 при частых запросах).
8. Заморозка 16–20 КБ — сторонний `dpi-detector` (тест `-t 3`) со списком целей из тест-IP,
   **с выключенным VPN на ПК**; на неясных — повтор на 443. Отдельно — с телефона (Termux) по
   мобильным операторам.
9. Оплату, верификацию и VPN в ToS — проверять по первоисточнику, не по пересказу.
10. После покупки: `vps_probe.py` на сервере, реальный туннель нашим клиентом, долгий поток с
    мобильного (шейпинг проявляется на длинных потоках), репутация IP у нужных сайтов
    (например, нет `cf-mitigated: challenge` в `curl -D -` с самого сервера).

Пример полного прохода (7 стран, шорт-листы, уроки): `MeerGuardNetwrokKnowledge/configs/stage/
2026-09-04-speedslots-access/docs/2026-09-15-hostery-po-stranam.md`; раньше — Польша
`…/docs/2026-09-11-polsha-hostery.md` и `configs/stage/2026-09-09-search-of-wl-twb/docs/2026-09-10-ip-triage-i-hostery.md`.

## Источники (все проверены, живые на 01.09.2026)

- Чёрные списки: `github.com/1andrevich/Re-filter-lists` (ipsum.lst), `github.com/eduard256/russia-blocked-ips` (ip.txt), `antifilter.download/list/subnet.lst`.
- Белый список мобильных: `github.com/hxehex/russia-mobile-internet-whitelist` (cidrwhitelist.txt).
- ASN → подсети: `stat.ripe.net` (без ключа), `github.com/ipverse/asn-ip` (fallback офлайн).
- Классификация ASN (тип сети): `peeringdb.com/api/net?asn=<N>` — Content/NSP/Cable/DSL/ISP/Enterprise. Отсутствие записи в PeeringDB — тоже сигнал (хостер не в точках обмена).
- Активная проверка IP из РФ: `check-host.net` (TCP-connect с 3 RU-нод), `globalping.io` API (ping + HTTPS handshake с 5 RU-проб).
- На VPS: `IP.Check.Place`, `vernette/ipregion` (гео-разрешение сервисами), Spamhaus DNSBL.

- 24940 Hetzner
- 14061 DigitalOcean
- 16276 OVH
- 60068 CDN77
- 199524 G-Core
- 20940 Akamai
- 13335 Cloudflare
- 16509 Amazon

## Стек

Python 3 stdlib, без сторонних пакетов. Запуск из папки `ip-triage/`.

## Ограничения (важно)

- `score.py` даёт **предварительную** оценку: пересечение адресов хостера с реестром РКН и белыми списками мобильных операторов. Реальную блокировку VPN-туннеля через ТСПУ он не измеряет.
- `probe.py` проверяет только «отвечает ли IP на TCP:443 и на пинг из РФ». Это дешёвый первый гейт: если IP не отвечает даже на пинг — точно мёртвый. Но если отвечает — это ещё **не значит**, что через него пойдёт Xray-туннель. ТСПУ спокойно пропускает TCP-handshake и рубит только реальный поток данных.
- **Настоящая проверка «работает ли VPN» возможна только после деплоя VPS**: подключиться к нему нашим клиентом и попробовать поднять реальный туннель. Этого этот инструмент не делает — только помогает сузить круг кандидатов ДО покупки.
- `country_whitelist.py` видит страну регистрации LIR, а не дата-центра: хостинг, зарегистрированный в другой стране, туда не попадёт — для него `country_score.py` по ASN.
- RIPEstat иногда не отвечает по отдельным ASN — такие строки в выгрузке пустые, перезапустить позже.
- Репутацию IP у Cloudflare и мобильный шейпинг до покупки не проверить.

## `vps_probe.py` — что запускать НА купленной VPS

Скрипт для запуска на самом сервере (Linux, Python 3, `bash` + `curl` + `ping` из base-системы). Собирает то, чего с моей машины не увидеть:

- Публичный IP сервера (через api.ipify.org).
- **IP.Check.Place** — прогон готового чекера, парсинг вердикта (репутация IP в 30+ blacklist-ах).
- **DNSBL Spamhaus** (zen/sbl/xbl/pbl) — чистый ли IP от спам-репутации.
- **Пинг** до 6 крупных RU-сайтов (yandex.ru, mail.ru, vk.com, gosuslugi.ru, sber.ru, ok.ru) — характеризует связность с РФ.
- **HTTPS-handshake** до тех же сайтов — работает ли исходящий 443 (некоторые провайдеры режут VPS-адресам исходящий трафик к РФ).
- Реверс-DNS (PTR).

Использование:

```bash
# на VPS:
curl -sL https://raw.githubusercontent.com/MeerGuard/meerguard_tools/main/ip-triage/vps_probe.py -o /tmp/vps_probe.py
python3 /tmp/vps_probe.py > /tmp/vps_probe.json

# у себя:
scp root@<vps>:/tmp/vps_probe.json ./reports/vps-<ip>.json
```

В stderr выдаёт короткое резюме: `spamhaus=[]  RU-ping=6/6  RU-https=6/6  ipcheck-hits=0` — если так, IP чистый и связность с РФ полная.
